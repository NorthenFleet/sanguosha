# 三国杀AI深度神经网络训练总体指导文档

## 1. 概述

本文档是三国杀AI系统深度神经网络训练的总体指导文档，详细描述了网络架构设计、状态空间建模、动作空间定义、训练策略以及具体的实施方案。本文档为后续各种算法（PPO、DQN、A3C等）的具体训练方案提供统一的理论基础和技术规范。

## 2. 游戏状态空间分析

### 2.1 状态空间维度分析

基于当前游戏实现，状态空间包含以下核心组件：

#### 2.1.1 玩家状态特征 (Player Features)
```
维度: 10维 × 2玩家 = 20维
- 当前血量 (hp): 1维 [0-5]
- 最大血量 (max_hp): 1维 [3-5]
- 手牌数量 (hand_count): 1维 [0-20]
- 武将身份 (character_id): 1维 [0-14] (15个武将)
- 装备状态 (equipment_status): 4维 (武器/防具/攻击马/防御马)
- 技能状态 (skill_status): 2维 (主要技能激活状态)
```

#### 2.1.2 手牌特征 (Hand Cards)
```
维度: 20张卡牌 × 16种卡牌类型 = 320维
卡牌类型编码:
- 基本牌: 杀(0), 闪(1), 桃(2), 酒(3)
- 锦囊牌: 无懈可击(4), 决斗(5), 南蛮入侵(6), 万箭齐发(7), 
         桃园结义(8), 五谷丰登(9), 借刀杀人(10), 顺手牵羊(11),
         过河拆桥(12), 铁索连环(13), 闪电(14), 乐不思蜀(15)
```

#### 2.1.3 装备特征 (Equipment)
```
维度: 12维
- 武器装备: 4维 (青龙偃月刀, 丈八蛇矛, 方天画戟, 麒麟弓)
- 防具装备: 3维 (八卦阵, 仁王盾, 白银狮子)
- 坐骑装备: 5维 (赤兔马, 的卢, 绝影, 爪黄飞电等)
```

#### 2.1.4 游戏阶段特征 (Game Phase)
```
维度: 6维 (One-hot编码)
- 准备阶段(0), 判定阶段(1), 摸牌阶段(2)
- 出牌阶段(3), 弃牌阶段(4), 结束阶段(5)
```

#### 2.1.5 棋盘状态特征 (Board State)
```
维度: 8维
- 牌堆剩余数量: 1维 [0-108]
- 弃牌堆数量: 1维 [0-108]
- 当前回合数: 1维 [0-∞]
- 当前玩家索引: 1维 [0-1]
- 游戏进行时间: 1维 [0-∞]
- 特殊状态标记: 3维 (铁索连环、延时锦囊等)
```

**总状态维度: 366维**

## 3. 网络架构设计原则

### 3.1 整体架构设计
- **算法框架**: 支持PPO、DQN、A3C等多种算法
- **网络类型**: Actor-Critic架构（PPO/A3C）或Q-Network架构（DQN）
- **输入处理**: 分层状态编码器
- **输出**: 动作概率分布 + 状态价值估计（或Q值）

### 3.2 核心网络组件
1. **状态编码器** (State Encoder) - 统一的状态特征提取
2. **策略网络** (Policy Network / Actor) - 动作概率输出
3. **价值网络** (Value Network / Critic) - 状态价值估计
4. **注意力机制** (Attention Mechanism) - 关键信息聚焦

## 4. 统一状态编码器设计

### 4.1 状态编码器架构
```
输入层: 366维游戏状态向量
  ↓
玩家特征编码器: 20维 → 64维
手牌特征编码器: 320维 → 128维  
装备特征编码器: 12维 → 32维
游戏状态编码器: 14维 → 32维
  ↓
特征融合层: 256维 → 512维 → 256维
  ↓
注意力机制: 8头 × 32维
  ↓
输出: 256维统一特征表示
```

```python
class AIPlayerService:
    def __init__(self, model_path):
        self.model = self.load_model(model_path)
        self.state_encoder = StateEncoder()
    
    def get_action(self, game_state, legal_actions):
        # 编码游戏状态
        encoded_state = self.state_encoder.encode(game_state)
        
        # 生成动作掩码
        action_mask = self.create_action_mask(legal_actions)
        
        # 模型推理
        with torch.no_grad():
            action_probs = self.model(encoded_state, action_mask)
            action = torch.multinomial(action_probs, 1).item()
        
        return action
```

## 5. 网络设计理念详解

### 5.1 为什么选择这些层数和神经元数量

#### 5.1.1 输入编码层 (2580→1024→512→256)
- **2580维输入**: 完整捕捉游戏状态信息
- **1024维第一层**: 初步降维，保留主要信息
- **512维第二层**: 进一步抽象，去除冗余
- **256维输出**: 平衡表达能力和计算效率

#### 5.1.2 注意力机制 (8头×32维)
- **8个注意力头**: 捕捉多种关系类型
- **32维每头**: 足够的表达能力，避免过度复杂

#### 5.1.3 策略网络 (256→512→256→128→动作空间)
- **先扩展后收缩**: 增强特征表达后聚焦决策
- **128维决策层**: 平衡决策复杂度和计算效率

#### 5.1.4 价值网络 (256→256→128→1)
- **保持维度**: 充分利用共享特征
- **逐步收缩**: 聚焦到单一价值输出

### 5.2 模块设计原理

#### 5.2.1 共享编码器
- **减少参数**: 避免重复学习相同特征
- **一致性**: 确保策略和价值基于相同状态理解

#### 5.2.2 注意力机制
- **关键信息聚焦**: 在复杂状态中找到关键决策因素
- **动态权重**: 根据当前情况调整关注点

#### 5.2.3 分离的输出头
- **专业化**: 策略和价值有不同的学习目标
- **稳定性**: 避免两个任务相互干扰
